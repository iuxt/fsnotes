# 渲染性能优化

日期：2026-10-08（Asia/Shanghai）。环境：Apple M1 Pro、16 GB、macOS 27.0.1、arm64 Release。
比较基线为 `a95ca044`，优化版本为本次工作区源代码。

## 实现

- 同一编辑器的语义代码块检测、样式、段落、图片选择与排版共用 Markdown 解析缓存。文本改变时重新解析一次；光标和属性变化复用解析结果。
- 使用 TextKit 编辑范围移动旧的隐藏字符与装饰位置，只使修改段落和语法显示变化的字符失效。局部编辑不再主动使全文字形失效。
- 段落样式只更新受影响的段落；未改变的表格不重复使字形失效。代码复制按钮、表格与图片命中检测按所需字符范围请求布局，标签装饰仅扫描重绘区域。
- 预览抓取独立内容快照，后台串行完成 Markdown 转换、解析和本地图片读取。新请求取消排队任务，并通过请求编号丢弃过时结果。
- WKWebView 复用页面和脚本，切换笔记只替换正文。移除图片预览时全局清空 WebKit 缓存和临时页面写入；本次渲染中的重复图片复用编码结果。
- TOC 直接操作标题节点；Mermaid 仅在正文含图表时加载，关闭自动重复初始化；代码高亮分批让出浏览器执行时间。
- 完成流程不依赖隐藏窗口中会暂停的动画帧。复选框、文件链接和滚动记录随已显示的笔记更新；清理与停止加载会取消后台工作，首次导航取消后可以重新加载。
- libcmark 扩展注册通过 Swift 一次性初始化，避免后台预览与原生编辑器首次解析时并发修改 C 注册表。

## 检查

- 即时 Markdown：114 项检查，包括共享解析、长文局部 Unicode 插入/删除、远处字形和隐藏语法位置。
- 原生表格：155 项检查。
- 自动保存、附件和图片：31 项检查。
- 任务、拖放等编辑操作：19 项检查。
- 解析器：首次 32 次并发解析；小笔记和长文各 100 次解析，HTML 哈希及预热后的内存增长检查。
- 完整应用：连续切换 250 次、开关预览 30 次、长文/代码/Mermaid、快速切换、公式重复渲染、图片与附件混排、消息目标、首次导航取消和窗口释放。

## 实测

完整应用计时使用项目现有的合成笔记和隔离测试应用，不操作用户笔记库。
端到端时间含编辑器填充、页面准备、代码高亮、Mermaid 和两次动画帧；轮询间隔为 20 ms，所以数值为近似测量。
MathJax 仅在功能检查中启用，不纳入计时工作负载。取消加载检查只验证加载与正文初始化，不要求隐藏窗口提供动画帧。

| 场景 | 优化前同步准备中位数 | 优化后同步准备中位数 |
|---|---:|---:|
| 小笔记连续切换 50 次 | 4.5 ms | 2.8 ms |
| 继续切换 200 次 | 4.5 ms | 2.9 ms |
| 约 525 KiB 长文 | 101.8 ms | 16.0 ms |
| 120 个代码块／3,600 行 | 20.8 ms | 10.2 ms |

最终完整应用回归退出码为 0，功能断言与窗口生命周期断言均通过；结束时已关闭的控制器、编辑器、文本处理器和 WebView 全部释放。Release 构建及 `git diff --check` 通过。

本轮有 82 次计时遇到测试窗口进入后台／被遮挡，已从端到端延迟样本中排除。长文、代码和 Mermaid 阶段没有有效动画帧计时样本，因此不据本轮数据宣称端到端显示时间或帧率的提升。上表是同步准备时间，仍可能受系统调度影响；首次打开 WebKit 只有一个样本，不用于性能比较。


原始基线位于 `.build/preview-performance/before-optimization/`；最终结果位于 `.build/preview-performance/`。
持续打字延迟、滚动帧率和大图片解码尚未做完整性能测量；局部编辑优化由解析次数、布局失效范围及语法回归检查验证。
