# UUID 笔记存储

每个资料库（默认存储目录、外部目录以及嵌套的 Git 仓库）保存自己的 `metadata.json`。
正文保存在 `notes/<uuid>.<扩展名>`，界面中的名称和文件夹由元数据定义。
图片和导入的外部附件保存在根目录 `images/`，正文使用相对链接引用。
资料库不创建实体 `Trash` 或 `trash` 目录；界面回收站由元数据查询生成。
改名、同资料库内移动、文件夹改名和移入回收站都不会改变正文路径。
复制会生成新 UUID；跨资料库移动保留 UUID，但两个 Git 仓库各自保留其历史。
删除只将元数据中的 `trashed` 设为 `true`，正文、附件、UUID 和原目录记录保留。
回收站永久保留笔记（包括空笔记），没有清空回收站或彻底删除入口；重复删除不删除文件。
撤销删除恢复原目录；原目录已删除时恢复到资料库根目录。

同目录内的可见标题按大小写不敏感的规则避重，依次添加 ` 2`、` 3` 等后缀。
回收站里的标题不占用原目录名称，可以重新创建同标题笔记；新笔记会获得独立 UUID。
恢复旧笔记时如标题已被占用，也会添加后缀，两篇笔记的正文互不覆盖。
不同目录允许相同标题。

## 数据与恢复

`metadata.json` 是唯一持久化的元数据快照，随笔记仓库同步。
打开资料库时从快照构建内存索引，按 UUID 直接查找记录，按目录读取分组；不创建本地数据库。
修改在文件协调和本地锁内执行，先读取当前快照，再原子发布 JSON，最后更新内存快照与索引。
记录按 ID 排序，字段按名称排序，无改动不会重写。
内存索引随资料库关闭而释放，重新打开时从 JSON 重建。

Git 管理正文、附件和 `metadata.json`。恢复整个快照会恢复名称、目录和回收站状态。
资料库的 `.gitattributes` 自动写入 `images/** filter=lfs diff=lfs merge=lfs -text`，包括所有子目录。
应用为 libgit2 注册 LFS clean/smudge 过滤器：Git 中保存标准 SHA-256 指针，图片原文保存在
`.git/lfs/objects/`，本地检出按哈希校验并还原图片，工作区始终使用正常图片文件。
macOS 推送前上传 LFS 对象，拉取和克隆后下载并还原图片。应用内置 `git-lfs`、Git 和钥匙串凭据助手，并以继承沙盒权限的辅助工具签名，
用户无需另外安装。macOS 构建机需要安装 Git LFS，或通过 `GIT_LFS_EXECUTABLE` 指定匹配目标架构的客户端；
缺失客户端或传输失败会报告错误，不会把原图当普通 Git blob 推送。
LFS 使用系统 Git 凭据和资料库 SSH 私钥；加密 SSH 私钥需要预先加入系统 `ssh-agent`。
iOS 支持本地 LFS 提交及缓存对象还原，目前不支持 LFS 远端传输，会明确报告此限制。
笔记的“恢复正文版本”只修改正文，不回退整个资料库的元数据。
主界面搜索框右侧的循环箭头按钮同步当前资料库，依次执行拉取、提交和推送。
没有本地改动时跳过提交，仍会推送已有提交；拉取或提交失败时停止后续步骤并显示错误。
同步期间显示进度，禁止重复点击。未配置仓库或远端时会提示打开 Git 偏好设置。
macOS 文件观察器、iOS iCloud 元数据更新、Git 拉取和重新打开资料库都会读取磁盘快照。
文件变动会更新内存笔记与目录。JSON 冲突、无效版本、重复 ID 或目录环会阻止元数据写入，
不会用旧内存快照覆盖损坏或未解决的 JSON；查询单篇笔记时仍可读取最后有效的内存索引。

数据示例（真实 ID 为 UUID）：

```json
{
  "version": 1,
  "folders": [
    {"id": "<folder-uuid>", "name": "技术"}
  ],
  "notes": [
    {
      "id": "<note-uuid>",
      "name": "Git 笔记",
      "folderID": "<folder-uuid>",
      "fileExtension": "md",
      "trashed": false
    }
  ]
}
```

`parentID` 为文件夹的父 ID，省略表示资料库根目录；`folderID` 同理。
`legacyPath` 保留迁移前的相对路径，用于查询旧 Git 历史，不能随界面改名修改。
Markdown 中现有的 frontmatter 会保留；界面名称由元数据决定。
自动命名设置会更新虚拟名称，而不会重命名正文文件。旧标题及改名前的名称保留为链接别名。
日常查询先检查文件时间、大小和 inode；未变动时直接读取内存索引，不重复解析 JSON。
外部快照变动时先完整解析和校验，再替换内存快照与索引；修改元数据前始终读取完整快照。
全量记录和目录分组均按 UUID 排序，保持查询结果稳定。
空文件夹也会保存在快照中。`.fsnotes-folders/<uuid>/` 只存放兼容现有文件夹功能的标记，
不存放笔记正文。`notes/.fsnotes-library` 标记已迁移的资料库。

## 首次迁移

新版本第一次打开旧资料库时会自动迁移 Markdown、纯文本和 Fountain。
iCloud 文件或元数据尚未下载时会发起下载并暂停迁移，下载更新后重试，避免发布空快照。
扫描跳过符号链接、隐藏目录、附件目录与旧回收站；嵌套 Git 仓库作为独立资料库处理。
已有的人类可读文件名变为虚拟名称；UUID 文件名会优先从原正文提取名称。
已有文件夹的层级、空目录、设置会保留。

迁移先生成 `.fsnotes-migration.json` 计划，再复制到临时文件并发布 UUID 文件，
随后原子发布快照，校验副本，最后删除旧正文。计划保留固定 UUID，支持中断后继续。
如果原件在中断期间被外部修改，会保留两份并报告错误，避免删除更新过的原件。
普通 Markdown 的本地行内/引用链接会按新位置重写；代码块和行内代码保留。
旧附件目录保留，文档通过相对路径引用它们。
文件导入会复制引用的本地资源，目录导入会先为所有笔记分配 ID，再重写内部链接。

迁移不会创建 Git 提交或重写提交历史。建议将首次迁移单独提交，便于审查路径变化。
迁移前的正文历史通过 `legacyPath` 查询，恢复时写回当前 UUID 文件。
此映射覆盖迁移时的旧路径；更早的历史重命名仍需要 Git 的重命名追踪。

已迁移资料库缺失 `metadata.json` 时会报告错误，保留 UUID 文件，避免重新分配身份。
未在快照中登记的 UUID 文件会保留在磁盘，等待元数据同步或显式重新导入。
已有的空 `Trash` / `trash` 目录在打开资料库时移除；非空目录不自动删除其中的文件。
